# Security tests

Every security claim Anvil's documents make, next to the test that proves it. A claim without a test is not listed here, and the documents do not describe it as a control. `crates/anvil-types/tests/docs_match_code.rs` (`every_test_named_in_security_tests_exists`) fails when a name in a `test` column below is not a function in the workspace, or is not defined in one of the files its `where` column lists, so a renamed or deleted test breaks the build instead of leaving a stale claim.

To run one test, name its crate and the test: `cargo test -p anvil-core a_host_outside_the_allowed_set_is_refused_before_any_connection`. The crate is the folder after `crates/` in the last column. Tests marked "Linux CI" run only on the Linux runner of `.github/workflows/ci.yml`; tests marked "Unix" or "Windows" run only there.

The identifiers in the first column (`NET-1`, `FS-3`, ...) are what README.md, SECURITY.md, docs/THREAT_MODEL.md and docs/CONTROLS.md cite.

## Checks that are not `cargo test`

These run in `just check` and in CI (`.github/workflows/ci.yml`) and are not test functions, so they are listed apart from the tables above.

- `cargo deny --all-features --locked check` against `deny.toml`: RustSec advisories, the license list, banned crates (OpenSSL, `native-tls`, other HTTP clients) and crates.io as the only source. Job `deny` in `ci.yml`; `just deny` locally.
- `anvil scan-keys`: no key shape or `.env` value in a tracked file (step of `just check` and CI).
- `just no-old-name`: the program's former name appears nowhere in the tree.
- `cargo clippy --all-targets -- -D warnings` with `clippy.toml`, which disallows `reqwest::Client` and `reqwest::ClientBuilder` outside `net.rs` (the lint half of NET-7), and the workspace lints `unsafe_code = "forbid"` and `clippy::unwrap_used`.
