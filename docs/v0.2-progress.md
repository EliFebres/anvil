## Phase 1: factory cost fixes

### Plan

Step 1 (`anvil-types`, `factory-review`):

- `factory_config.rs`: optional `blocking` on `[[reviewers]]` (default true for correctness and safety, false for style and simplicity); validation needs at least one blocking reviewer; optional `[eval_gate] paths` (globs, validated); template comments.
- `factory-review`: `ReviewerId.blocking`; `Verdict::aggregate` sets every finding of a non-blocking reviewer aside as a comment; `review()` reruns only the failed reviewers up to two more times with a delay and keeps the delivered reviews; `Verdict.failed` names reviewers that still failed; `prompts/style.md` loses the "major because it fails the build" sentence (snapshot accepted).

Step 2 (`factory-core`, `factory-cli`, docs):

- `worker.rs`: order A, C, release build, B; Gate B skipped when no changed path matches `[eval_gate] paths`; a still-failed reviewer stops the ticket without an implementer run; per-gate cost records.
- `render.rs`: `fix_task` for review fix rounds; gate records with a skipped result; cost table in the pull request body.
- `status.rs`, `board.rs`, `ports.rs`: `GateCost` in `Outcome`, `OutcomeRecord` (`outcomes.jsonl`) and the dashboard snapshot; `Stage::ALL` in the new order.
- `factory-cli`: adapter passes tokens and failed reviewers through; `factory watch` snapshots; selftest label.
- `README.md`, `deploy/nuc/README.md`, `factory.toml`.

### Decisions

- Fix rounds use option (b): a fresh session whose task says the change is already on the branch, names the changed files and lists only the findings. Option (a) was not simpler: `anvil resume <id>` takes no new instruction and the factory does not capture the session id, so (a) would need changes in `anvil-cli` and the sandbox.
- A reviewer that still fails after its reruns pauses the ticket (`Outcome::Paused`): an unreachable review provider is the factory's failure, not the ticket's, the same reading as #12 took for container failures.
- The "do not undo an earlier round's fix" behavior stays where `acabdb3` put it: `earlier_findings` in the reviewer prompt.

### Result

- A failed reviewer returns `Outcome::Paused`, which pauses the factory service as every other pause does; the ticket is reopened, not lost.
- `EvalGateReport` and `ReviewReport` carry `Tokens`; the worker weights them. An eval report without token counts records `-`.
- A skipped Gate B adds only the gates-table row to the pull request body, no eval section.
- `factory selftest` was not run locally (see "Local checks"); the `selftest` CI job runs it on every push.

## Phase 2: planner, builder and reviewer roles

### Plan

- Part A (`anvil-types`, `anvil-core`): optional `[roles] planner`; `LoopProviders.planner: Option<..>`; Plan on the planner; a new coder conversation seeded with the task and the plan; escalation; spend per role.
- Part B (`anvil-cli`, `anvil-telemetry`, `eval`, factory): telemetry and cost per role, eval schema 2 with every role's model, config surface, factory planner, reviewer rule by base URL and model.

### Decisions

- `planner` is `None` in the loop unless it names a different provider than `coder`, so a config without it sends byte-identical requests. A request snapshot of a scripted session, written before the loop changed, proves it.
- The build conversation is logged as a `Rebased` session record; a resume past Plan restores it.
- Escalation thresholds are the constants `ESCALATE_AFTER_CHECK_FAILURES = 2` and `ESCALATE_AFTER_REVIEW_CHANGES = 2`. The counters count consecutive failures, live on the loop, and are not restored on resume. One Build round runs on the planner, on the same build conversation.
- Per-role output (stats table, status line breakdown, summary lines) appears only when a planner is configured, so everything without one prints as before. `summary.md` shows tokens per role, not cost: the core has no prices.
- Eval: `SCHEMA_VERSION` is 2; schema 1 still reads; the top-level `model` stays the coder's, so file names, `eval compare` and Gate B work against the baseline on `main`.
- Factory review rule: a reviewer must differ from the coder in base URL or model; the blocking reviewers must cover at least two models; a reviewer may equal the planner. The old rule "two differently named reviewers never share a URL" is gone.
- `/model <name>` still switches only the coder; `/model` lists the planner.
- Compaction in `status.json` is priced at the summarizer's price (it was the coder's in the first phase 4 commit).

## Phase 3: cheap workers

### Decisions

- The loop asks a generic `Tool::parallel_safe`; consecutive calls that answer yes run together, at most four at once, and results and events keep call order. A call that may write ends a group.
- `implement` reaches the owner's permission prompt through a new agent key, `permissions: inherit`. Every other agent keeps answering no to an `ask` rule.
- Because the built-in agents always exist, `delegate` is registered in every session and the system prompt lists `explore` and `implement`. That is a prompt change for every run; the next eval baseline is not comparable turn for turn with the one on `main`.
- While planning, a call whose tool says `may_write` is refused with an ordinary failed result (not a denial, so the run is not marked denied). This closes a hole the built-in `implement` would otherwise have opened: `delegate` is a read tool, so Plan offers it.
- Delegated turns are booked under `worker` and priced at the worker provider's price even when the agent's `model` names another provider: the turn event carries only the role. Compaction inside a subagent counts as a worker turn.
- The budget is shared with no new mechanism: every provider is wrapped in the one session budget.

## Phase 4: session status signal

### Decisions

- `SessionStatus` lives in `anvil-types`; the tracker (a pure state machine) and the writer live in `anvil-cli/src/status/`. Prompts are caught by wrappers around the permission prompt, the plan gate and the memory decider, above both front ends, so `--plain` is byte-identical.
- Liveness: the session holds `File::try_lock` on `status.lock`; `anvil status` shows `stale` when the lock is free. This needed `rust-version` 1.89 (was 1.88; the pinned toolchain is newer).
- `--all` reads a new registry `~/.anvil/projects/<hash>` written by each session, because telemetry stores only a digest of the project path. Sessions from before this change are not listed until the project runs again.
- `done` or `blocked` is written after the memory step, not on the loop's `Finished` event.
- Notifications: a second small sender in `anvil-cli` (the crate boundaries forbid sharing the factory's). One message per entry into a state.
- Herdr: built. The documented environment (`HERDR_ENV`, `HERDR_PANE_ID`, `HERDR_BIN_PATH`) identifies the pane. `needs_input` and `blocked` report `blocked` with the detail; `done` and `failed` report `idle`, then release on exit. `--seq` is the Unix time in milliseconds.
- An idle chat waiting for the next message stays `working`.

## Phase 5: learning how I work

### Decisions

- Rules are filtered by the project's languages (a bounded walk honoring `.gitignore`, 5,000 files, depth 8). A rule for a language the table cannot detect is always kept. The reviewer gets the same set: the changed files are not known where the sections are built.
- Corrections are recorded in `~/.anvil/memory/corrections/<repo>.toml` with a SHA-256 and a copy of the text (32 KiB per file, 128 KiB per record) rather than through git, so uncommitted work is covered. The diff sent to the model is capped at 16 KiB.
- Under `--yes` the start-of-session proposal step is skipped; `anvil memory learn` picks the edits up later.
- Proposals are rules with one language and no mechanical check; the text says when one is realistic.
- `anvil new` treats a directory holding only dot-directories as empty. The template list reaches the prompt through `sections`, so it is in every coder state of that session, not only Plan.

## Phase 6: long builds

### Decisions

- All types live in `anvil-cli/src/build/`; `anvil-types` is unchanged.
- The plan is a fenced JSON block, at most 30 items, re-asked once when malformed.
- `.anvil/` is excluded from the clean-tree check and from every build commit, so the spec file must be committed or live outside the repository.
- The build reuses the session status writer on `.anvil/builds/<id>/status.json`. `anvil status` does not list builds; `anvil build status` does.
- Inside a build each item's plan is approved at once, and the memory and learn-from-edits prompts are skipped.
- Budget share per item: the smallest of the session limit, remaining tokens divided by items left, and remaining USD divided by items left at the coder's price. USD is enforced inside a session only when the coder has a price.
- A failed attempt is committed on `anvil-build/<id>/item-<n>-attempt-<k>`; the build branch is never moved back.
- Because the checks decide, a session that stopped early but whose checks pass is committed as done.
- Session approvals granted during one item ("for this session") carry into later items, because they share the approval store.

## Local checks

Smart App Control on the development machine blocks `just.exe` and binaries built into the repository's `target/`. The steps of `just check` are run by hand with `CARGO_TARGET_DIR` pointing at a temporary directory: the old-name `git grep`, `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all --no-fail-fast`, `scan-keys`. The anvil-cli tests that launch the built `anvil.exe` (`tests/cli.rs`, one doctor test) are blocked locally with os error 4551. Draft pull request #41 was opened early so CI runs the real `just check` on Ubuntu and Windows, plus the selftest, on every push; a commit counts as checked when that run is green.

Phases 2, 3 and 5 were developed in git worktrees (branches `v02-phase2`, `v02-phase5`) and merged into `dev` when reviewed. Implementation was delegated to Sonnet helpers in herdr panes; planning and review stayed in the main session.

CI caught one thing the local run could not: the request snapshot recorded CRLF from the prompt files on Windows and failed on Ubuntu (`e7d1ff3` normalizes it).
